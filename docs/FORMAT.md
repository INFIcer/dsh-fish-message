# 出站格式：`[QQ]` 块、转义、显式指令

这份文档只讲 **DSH → QQ** 的正文格式。QQ → DSH 的方向是收到什么转什么，不经过这里。

---

## 1. 最基本：只发块内

设置页默认打开「只发 `[QQ]…[/QQ]` 块内」。

```text
这句是我的思考，只留在 DSH。

[QQ]这句会发到 QQ。[/QQ]

这句也留在 DSH。
```

手机上只收到：

```text
这句会发到 QQ。
```

### 规则

- 标记大小写不敏感：`[qq]…[/qq]`、`[QQ]…[/QQ]` 都认。
- 标记中间允许空格：`[ QQ ]…[ / QQ ]` 也认（兼容旧桥）。
- 块外内容不发，但仍保留在 DSH 会话里。
- 一个块都没有：这一轮不往 QQ 发。
- 空块（只有空白）：不发。

---

## 2. 多个块

多个块按出现顺序拼接，中间用换行：

```text
[QQ]第一段[/QQ]
这里的字不发
[QQ]第二段[/QQ]
```

QQ 收到一条：

```text
第一段
第二段
```

---

## 3. 只写开头，没写结尾

保留旧桥的容错：`[QQ]` 之后全部算要发的，直到正文结束。

```text
前面不发 [QQ]第一行
第二行
第三行
```

QQ 收到：

```text
第一行
第二行
第三行
```

---

## 4. 转义（重点）

QQ 里要出现字面量 `[QQ]` / `[/QQ]`，必须转义；否则会被当成标记，把块提前关掉。

### 4.1 转义表

| 你写的 | 实际发出去的 |
|---|---|
| `\[` | `[` |
| `\]` | `]` |
| `\\` | `\` |
| `\/` | `/` |

反斜杠只对上面几个字符生效。Windows 路径里的 `\` 不会被误吃：

```text
[QQ]文件在 D:\dsh_ws\a.txt[/QQ]
```

QQ 收到 `文件在 D:\dsh_ws\a.txt`。

### 4.2 扫描顺序

1. 先按「未转义」扫描 `[QQ]` / `[/QQ]` 标记；
2. 找到块后，只对块内文字做反转义；
3. 多个块全部拼接。

所以 `\[QQ]` 永远不会开启一个块；`\\[QQ]` 里的 `[QQ]` 会开启（因为两个反斜杠先还原成一个 `\`，`[` 没被转义）。

### 4.3 发送字面量 `[/QQ]`

在块内，下面两种写法都可以（`[` 前面加一个反斜杠）：

```text
[QQ]写法一：\[\/QQ] 结束[/QQ]
[QQ]写法二：\[/QQ] 结束[/QQ]
```

也就是说，要发送的字符序列是「反斜杠 + `[` + 反斜杠 + `/` + `QQ]`」或
「反斜杠 + `[` + `/` + `QQ]`」。两种都会让标记扫描器认为 `[` 被转义了，
块不会在这里结束；反转义后就是字面量 `[/QQ]`。

两种都会在 QQ 里显示：

```text
写法一：[/QQ] 结束
写法二：[/QQ] 结束
```

同理，字面量 `[QQ]`：

```text
[QQ]字面量 \[QQ] 不会开启新块[/QQ]
```

QQ 收到 `字面量 [QQ] 不会开启新块`。

> 注意：如果你在块内直接写未转义的 `[/QQ]`，块会在这里结束，后面内容变成块外，不会发送。

## 5. 代码块 / 行内代码

约定：**代码块和行内代码里的 `[QQ]` / `[/QQ]` 不算标记，直接当普通文本。**

### 行内代码

```text
看这个 `[QQ]`，它是文字，不是标记。
```

- 「只发标记内」开着：没有真正的块 → 不发。
- 关掉：整条发，反引号里的 `[QQ]` 原样保留。

### 围栏代码块

````text
说明
```
[QQ]这不是要发的[/QQ]
```
结束
````

同样：里面的标记不参与识别。

### 如果代码块在真正的 QQ 块里面

```text
[QQ]
示例：
`[QQ]` 和 `[/QQ]`
[/QQ]
```

代码块里的内容会作为块内文字发出去，因为外层块是真的；但代码里的标记不会额外开启/关闭外层块。

---

## 6. 关掉「只发标记内」

设置页把「只发 `[QQ]…[/QQ]` 块内」关掉后：

- 整条正文都发；
- 标记本身仍然剥掉（不会把 `[QQ]` 发到手机）；
- 代码块里的标记**不剥**（按第 5 节约定，它们是文本）；
- 转义仍然生效。

例子：

```text
前 [QQ]中[/QQ] 后
```

QQ 收到 `前 中 后`。

## 7. 显式指令

块内（或关掉开关后的整条正文）可以写：

### 7.1 图片

```text
[图片:C:\pics\a.png]
[图片:https://example.com/a.png]
```

- 本地路径必须是本机存在的文件；
- 本地图会读成 base64 再交给 NapCat，避免 NapCat 读不到路径；
- 网络图直接把 URL 交给 NapCat。

### 7.2 语音（TTS）

```text
[语音]晚安，主人[/语音]
```

- 调本地 `POST /tts`，默认音色 `dafeiyu`；
- 合成后发 `record` 段；
- 这段文字不会另外再发一遍纯文字。

### 7.3 已有音频

```text
[语音:C:\audio\a.wav]
[语音:C:\audio\a.mp3]
```

直接当语音条发；NapCat 会自己转成 QQ 的 amr。

### 7.4 文件

```text
[文件:D:\docs\a.pdf]
```

依赖 NapCat 是否支持 `file` 段；不支持会报错，不会静默成功。

### 7.5 混排

```text
[QQ]先听这句：[语音]晚安[/语音]
再看这张：[图片:C:\pics\a.png][/QQ]
```

按出现顺序发送：文字 → 语音条 → 图片。

### 7.6 表情包

```text
[QQ]给你一个：[表情:打哈欠][/QQ]
[QQ]随机来一张睡觉的：[表情:#睡觉][/QQ]
[QQ]按 id 精确发：[表情:3b23f496681f][/QQ]
```

- 名字 = 设置页「表情包」里显示的文件名（可省略扩展名）、`#标签` 或 id；
- 标签/文件名/描述是**大小写不敏感**的模糊匹配；`#标签` 精确匹配标签；
- 一次可以写多个表情，按出现顺序发送；
- GIF 按图片段发，NapCat 会保留动图；
- 发送成功后库里的 `used_count` / `last_used_at` 会更新（补发成功的也计）；
- **找不到时不会静默**：日志和状态里记一条错误，并在当前 DSH 会话里投一条
  「找不到表情：xxx」的提示，列出可用的写法。

多个表情混排：

```text
[QQ]先文字 [表情:晚安] 再语音 [语音]晚安[/语音] 最后 [表情:#生气][/QQ]
```

## 8. 常见错误

| 现象 | 原因 | 改法 |
|---|---|---|
| 手机没收到 | 没写 `[QQ]` 块，或块是空的 | 检查块；或关掉「只发标记内」 |
| 只收到半句 | 块内写了未转义的 `[/QQ]` | 写成 `\[\/QQ]` 或 `\[/QQ]` |
| 手机看到 `[QQ]` 字样 | 想发字面量但没转义，或关开关后代码块里的标记 | 字面量写 `\[QQ]`；代码块约定见第 5 节 |
| 图片没发 | 路径不存在 / 超过 `maxImageMB` | 看设置页日志 |
| 语音没发 | TTS 没启动 / 音色名不存在 / 超过时长 | 看 `/dsh-fish-message/state` 的最近错误 |
| 文件没发 | NapCat 不支持 `file` 段 | 改用图片/文字，或升级 NapCat |
| 表情没发 | 名字/标签/id 不在库里 | 看会话里的「找不到表情」提示；到设置页「表情包」确认名字，或改用 id |
