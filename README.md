# dsh-fish-message

DSH 的 QQ 私聊通道。它把 QQ 私聊与 DSH 会话连接起来，双向传递文字、图片和语音文件，
并在 DSH 未运行或 QQ 暂时离线时保留消息、等待恢复后补发。

---

## 1. 用途

- 在 QQ 私聊与 DSH 会话之间互传消息，目前仅支持私聊。
- 支持文字、图片、语音文件的收发，以及普通文件的发送。
- 支持按名称或标签发送表情包，并可管理自己的表情包。
- DSH 或 QQ 未运行期间收到的消息，会在恢复后补发；暂时发不出去的消息先保存在本机，
  恢复后按顺序重试，不会直接丢失。
- 语音合成、语音分析和入站图片识图由可选的「本地 AI」插件提供；没装时其它功能照常。
- 收到的图片按内容指纹缓存识别结果；同一张图再来直接用上次的描述，不再重复识图。
- 装了「记忆」插件后，可把收到的图片、语音与记忆图库、声纹库比对，把识别结果附在消息正文上。

---

## 2. 安装

### 2.1 准备

- 已安装并可正常使用的 DSH。
- 本机已安装 QQ 登录服务（如 NapCat），并已登录需要使用的 QQ 号。
- Node.js 20 或更高版本。

### 2.2 安装插件

在本目录执行：

```powershell
pnpm install
dsh plugin --profile desktop add .
```

然后确认 DSH 的插件配置中已启用鱼讯。

### 2.3 避免重复接收

如果之前使用过其他 QQ 桥接插件，请先停用，否则同一条 QQ 消息会被处理两次。

### 2.4 生效

安装或更新插件后，下一次 DSH 启动时加载。启动后打开「设置 → 鱼讯 QQ」。

> 若当前正在 DSH 会话中，让 DSH 重新加载插件会结束该会话，请另开一个终端执行。

## 3. 使用

### 3.1 连接 QQ

在设置页「连接设置」中填写 QQ 登录服务地址；服务启用了鉴权时再填写访问令牌。
连接正常时，页面顶部显示「在线」。

需要识别好友撤回时，还要在 QQ 登录服务里打开 WebSocket 服务端（NapCat 的「WS 正向
服务器」，通常与 HTTP 端口不同，例如 `ws://127.0.0.1:3001`），勾选「优先实时接收」，
并把「实时接收地址」填成那个地址；留空时按 HTTP 地址推导。只用定时查询也能正常收发，
只是看不见撤回。

### 3.2 绑定会话

在「私聊绑定」中，为每个 QQ 号选择一间 DSH 会话。关闭「启用」后，该 QQ 号不再收发消息。
每行第一列的称呼仅用于区分不同联系人。

绑定也可以在会话里直接切换，不必打开设置页（见 3.3）。

### 3.3 在会话里切换收发渠道

会话输入框左侧有一个「收发渠道」按钮，点开后选择这个会话收哪个 QQ 的私聊：

- 选中某个渠道：这个会话改为接收它的消息。
- 选中「不绑定」：这个会话不再接收 QQ 消息。渠道本身保留，设置页里还能再绑。
- 一个渠道只能绑定一个会话。选中一个已经绑在别处的渠道时，绑定会转移到当前会话，
  原来那个会话回到未绑定。

菜单里的渠道来自设置页「私聊绑定」，只列启用中的；当前会话绑着的那条即使被禁用也会
显示出来。另一个会话里的按钮不会立刻跟着变，点开或切回会话时会重新读取。

### 3.4 发送消息

DSH 的回复默认只发送 `[QQ]…[/QQ]` 标记内的内容，其余部分留在 DSH。若希望整条回复都发送，
可在「消息处理」中关闭该限制，此时标记本身会被去掉。

一个 `[QQ]` 块就是一条 QQ 消息：写几个块就发几条，顺序与书写顺序一致。块与块之间的文字
不会发出去，也不会被拼进相邻的块。

```text
[QQ]这段会发送到 QQ。[/QQ]

[QQ]第一段（单独一条消息）[/QQ]
[QQ]第二段（也是单独一条消息）[/QQ]
```

### 3.5 发送图片、语音与文件

```text
[图片:C:\图片\示例.png]
[语音]晚安，主人[/语音]
[语音:C:\音频\示例.wav]
[文件:D:\文档\示例.pdf]
```

本地 AI 插件可用时，`[语音]文字[/语音]` 会把原文交给本地 AI 服务合成语音条；
文字过长时按句子切成多条语音依次发送，不会截断。朗读化（数字、单位、符号等
转成中文读法）由本地 AI 服务统一处理。也可以用 `[语音:路径]` 直接发送本机已有
的音频文件。插件没装或没启动时，语音相关功能会给出提示，
文字、图片、文件和表情照常收发。文件能否发送成功，取决于 QQ 登录服务的版本与权限。

收到图片或表情包时，不管本地 AI 插件是否可用，第一次都只按内容指纹登记、不识别，
原图照常作为附件和路径递进会话（见 3.7）。同一张图第二次出现时才会在本机识别一次，
把描述写进收图图库；之后再来直接用描述，不再识图，也不再塞原图。
提示词可在设置页「本地 AI 服务 → 图片识别提示词」中修改，留空使用默认。
要看原图时让智能体调 `fish_image_get`。

### 3.6 表情包

在设置页「表情包」中可设置保存位置、自动保存、数量上限与占用空间上限，并点「打开图库管理」
在设置页之上打开表情库弹窗（见 3.8）。表情库里可以上传、搜索、编辑标签与描述、删除、
直接发送，以及一键打开表情库文件夹。

发送表情时，可使用名称或标签：

```text
[表情:打哈欠]
[表情:#睡觉]
```

找不到对应表情时会在 DSH 会话中提示，不会静默跳过。

### 3.7 收图图库

收到的图片会按内容指纹（sha256）在图库里登记原图。收图大多不会反复使用，所以
第一次只登记、不识别：

- 第一次见到：只登记原图和指纹，把原图递进会话；不调识图，也不要求智能体补描述；
- 第二次及以后、还没有描述：按「收到图片后先在本地识图」的设置识别一次，补上描述，
  并在消息里说明「这张图第 N 次见到，收图图库已自动补上描述」；之后同一张图再来只给描述、不附原图；
- 第二次及以后、本地识图关着：把原图递进会话，说明「这张图第 N 次见到，收图图库还没有描述；这次直接看图」，
  不要求补描述；
- 识图失败：退回原图，描述下次再补；
- 有描述：直接命中缓存，不再识图，也不再往上下文里塞原图；正文会写明「来自收图图库（缓存），第 N 次见到」。

「第 N 次见到」按命中次数 + 未命中次数算：第一次见到记未命中，之后每次记命中，所以从 1 开始、
每收到一次这条图 +1。图库里的「命中 N 次」就是这张图被复用的次数（第一次见到不算命中；
如果第一次就从表情库借到了描述，描述当场可用，算一次命中）。

图库是缓存：超过条数或占用上限会自动淘汰最久没见到的图片，不提示；表情包是收藏，
永远不会被自动删除。默认位置在 DSH 家目录下的 `fish-message-images`。

收到的图都会先进收图图库，但只有开了自动保存或被手动存下的图才会进表情库——两者是两套
独立存储（各自的目录和索引）：图库淘汰不会删表情库的原图，表情库删除也不影响图库。
命中回执会说明描述来自哪个库；如果这张图早被存成表情包（表情库里有它的描述），收图图库
缺描述时会直接借用，回执写明「来自表情库（这张图已存为表情包）」，并把描述写回收图图库，
下次就命中缓存。表情库/表情包照旧：存表情时仍要求填描述，也不套用收图图库「第一次不识别」的策略。
两个库的分工不变。

命中缓存时只给描述。需要亲眼看原图时，让智能体用工具取：

| 工具 | 作用 | 代价 |
|---|---|---|
| `fish_image_get` | 按内容指纹（或本机图片路径）取回图库里的原图：能看图时直接返回图片，否则返回本机路径 | 原图占上下文，比读描述贵；要细节才取 |
| `fish_image_note` | 给某张图写或改描述（回执里会说明是否覆盖了旧描述） | 不改图片本身，只改缓存 |

设置页「收图图库」里的选项：

| 设置项 | 默认 | 说明 |
|---|---|---|
| 收图先查图库 | 开 | 关掉后完全退回旧行为：每次按识图设置重新识别，不查库也不写库 |
| 图库条数上限 | 1000 | 超过上限时淘汰最久没见到的图片 |
| 原图占用上限（MB） | 512 | 只算图库自己存的原图 |
| 在图库里存原图 | 开 | 关掉只留描述与尺寸；入站缓存被清理后就没法回看原图 |

图库与本地 AI 插件无关：没装本地 AI 时，已有描述的图照样能用缓存；没描述的图第二次出现时
也只能直接看图。

### 3.8 图库管理

表情库与收图图库各自有一个设置内弹窗：在「设置 → 鱼讯 QQ」的「表情包」或「收图图库」块里点
「打开图库管理」，打开的就是自己那个库的弹窗，盖在设置页之上，不会把设置页顶掉。
弹窗里没有页签，也不会显示或跳到另一个库；同一时间只开一个。

两个弹窗共用同一份交互模板：

- 顶部：库名标题（「表情库」或「收图图库」）与关闭按钮；
- 工具条：左搜索框（搜索名称、描述或标签），右刷新与本库的库级操作；
- 内容区：图片卡片网格；点卡片进详情，左上「返回」回网格；
- 底部状态行：最近一次操作结果，失败时保留现场。

| 弹窗 | 看什么 | 能做什么 |
|---|---|---|
| 表情库 | 本机表情包网格 | 上传、搜索、改标签与描述、复制路径、发送、删除；库级操作为打开表情库文件夹、删除未使用、清理重复 |
| 收图图库 | 本机收图缓存 | 看缩略图、尺寸、占用、命中次数、描述来源与加入时间；改描述、存为表情、打开原图；库级操作为清空图库、打开图库文件夹 |

设置页里「表情包」与「收图图库」两块相邻，各自末尾有「打开图库管理」主按钮；两个库的配置项
（保存位置、自动保存、上限、是否存原图等）仍留在设置页，弹窗只做浏览与单条操作。

实现上是「一份模板 + 两个变体」：弹窗壳、工具条、卡片网格、详情壳、二次确认、状态行、
空态/加载态都在模板里，两个变体只提供自己的数据、卡片字段、详情字段和库级操作。
以后统一改交互或视觉只改模板一处；某个库要加自己的东西只改它的变体，不复制模板代码。
加载态统一为「正在读取图库…」，空态统一为「图库是空的。」。

危险操作（删除表情、清空收图图库、删除未使用、清理重复）都在弹窗内二次确认，不再用浏览器的
`confirm`。Esc 只关弹窗（二次确认打开时只关确认框），不会连带关掉设置；点遮罩也能关闭。打开时
焦点进入面板，关闭后回到刚才的入口按钮。

「存为表情」把这条缓存的原图存进表情库，来源记为 `qq-inbox`；同一张图已经在表情库里时只合并
描述，不会重复保存。旧的「最近收到的图片」列表与「清空最近图片」按钮已移除：入站图片统一进
收图图库，要留作表情就在「收图图库」详情里点「存为表情」。

记忆图库与声纹库不在这个弹窗里：它们由记忆插件自己的页面管理；鱼讯只保留入站消息的「记忆扩展」
比对（见 3.9）。

### 3.9 记忆扩展

安装并启用「记忆」插件后，鱼讯可以把收到的图片、语音与记忆插件提供的记忆图库、声纹库比对，
把识别结果附在消息正文上，不需要智能体主动调用工具。默认关闭，在设置页「记忆扩展」中开启。

| 设置项 | 默认 | 说明 |
|---|---|---|
| 开启记忆扩展 | 关 | 总开关；关闭时不调用记忆服务，两个子开关也不生效 |
| 比对图像 | 开 | 与记忆图库按内容指纹比对；只在本机算指纹，不发图 |
| 比对声纹 | 开 | 与声纹库按声音认人；需要本地 AI 服务在运行 |

比对口径：

- 图片命中且有描述：正文追加「（记忆：描述｜标签：a、b）」；
- 图片命中但没有描述：追加「（记忆：这张图在图库里〔标签：a〕，还没写描述）」；
- 图片未命中：不追加任何内容；
- 语音认出：追加「（记忆：声音来自名字，相似度 0.83）」；
- 语音认不出、声纹服务不可用：只记日志，正文保持不变。

降级行为：没装记忆插件、记忆服务抛错或超时（单次最多等 5 秒）都只跳过比对，消息照常收发。
第一次探测不到记忆服务时只提示一次，不会每条消息刷日志。声纹比对开着但本地 AI 没运行时，
只跳过声纹，图像比对照常。设置页「记忆扩展」卡片里的「记忆服务」「本地 AI」两行显示当前状态。

与收图图库、表情库的关系：记忆扩展只读记忆库，不参与收图图库的缓存与淘汰，也不会把 QQ
新图自动存进记忆图库——记忆库是长期收藏，入库由智能体显式调用记忆工具；表情库同样不受影响。

### 3.10 离线补发与待发消息

DSH 或 QQ 未运行期间收到的消息，会在恢复后按时间顺序补发；超过「离线消息补发范围」的旧消息
只发送一条汇总提示。暂时发不出去的消息会先保存在本机，可在「待发消息」中查看积压情况、
立即重试或清空。清空后这些消息不再补发。

补投回来的历史同样会按「编辑窗口」分组合并（见 3.11）：时间差小的算一批，时间差大的分开投，
不会丢消息，也不会把相隔很久的几句话糊成一段。

### 3.11 编辑窗口与发送节奏

**编辑窗口**：收到消息后不立刻转进会话，而是等主人「停下来」再合并投递，避免半截话和
「发完又撤回」的内容进入会话。

| 设置项 | 默认 | 说明 |
|---|---|---|
| 编辑窗口（秒） | 15 | 最后一条消息之后静默这么久（0~120），才把这一批合并成一条递进会话；范围内每来一条就重新计时。0 = 不合并，逐条递进 |

- 合并口径：正文按时间顺序换行拼接，图片按顺序汇总进同一条消息；每条消息的去重、
  水位、统计仍逐条记。
- 好友撤回（需要 WebSocket 连接，见 3.1）：还在窗口里的消息直接从待投队列删掉，不会
  进会话；已经投递的撤不回来，只记日志。窗口空了就什么也不投。
- 计时按消息自带的发送时间算，不是按「插件什么时候读到它」：离线补拉的历史如果早就
  过窗口，会立刻投递，不会白等 15 秒。

**发送节奏**：让回复像在一条条打字，而不是瞬间刷屏。

| 设置项 | 默认 | 说明 |
|---|---|---|
| 发送间隔（毫秒） | 2000 | 每条消息发出前固定等这么久（0~60000）；0 = 立即发送 |
| 按字数追加间隔（毫秒） | 100 | 在固定间隔之上按字数再加（0~5000）；0 = 不按字数等 |

字数口径：中文、日文、韩文每字算 1；英文等拼音文字连续一串算 1 个词（不按字母算）；
连续数字串算 1；标点、空格、符号各算 0.2；图片、文件和语音文件不算字。等待只发生在
发送前，不改变发送顺序，也不影响收消息。

多个 `[QQ]` 块算多条消息：每块按**自己**的字数单独等待，不会合并成一段只等一次；
块内有多条指令（文字、图片、语音）时也逐条等待。

### 3.12 日志

设置页底部显示最近日志，可滚动查看。日志只保留最近一段时间，重启后重新开始记录。

## 4. 已知缺陷

- 仅支持私聊，群聊暂不支持。
- 文件发送依赖 QQ 登录服务的版本与权限，部分环境可能无法发送。
- 待发消息严格按顺序补发：前一条长期发送失败时，后面的消息会一起等待。
- 极少数情况下补发可能重复一次（消息已送达但记录尚未清除时）。
- 表情包预览使用原图，较大的动图加载会稍慢。
- 表情包达到上限后需要手动清理，不会自动删除旧表情。
- 更换表情包保存位置后，原有图片不会自动迁移。
- 语音合成、语音分析和入站图片识图依赖可选的本地 AI 插件；没装时这些功能不可用
  （收图图库本身不依赖它，但没描述的图第二次出现时也只能直接看图）。
- 收图图库满了会淘汰最久没见到的图片，淘汰后同一张图再来会重新登记（第一次不识别）。
- 记忆扩展依赖「记忆」插件；没装或没启用时该功能不可用，消息照常收发，只是不附比对结果。
- 撤回只在开启 WebSocket 时可见：只用定时查询时，被撤回的消息不会再补投，但已经投递的
  消息无法收回。
- 消息合并投递后，DSH 会话里看到的是一条包含多行正文的消息，不是原来的多条消息。
